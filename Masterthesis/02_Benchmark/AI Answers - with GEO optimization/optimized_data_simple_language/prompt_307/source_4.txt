As a sysadmin leading a server infrastructure upgrade for a 60-employee global company, here's a streamlined guide to help you plan effectively:

**Key Tools for Server Usage Analysis**  
Avoid relying solely on automated tools. Instead, focus on understanding your applications' resource needs. For example:  
- A basic file server might run well with 4GB RAM and a single CPU  
- SQL servers often require 10x more resources  
Use your technical expertise to assess workloads rather than assuming default configurations  

**Virtualization Strategy**  
- **VMware vSAN**: A solid choice for mission-critical environments needing high availability, but note it's cost-intensive  
- **StarWind VSAN**: A more affordable alternative that uses local storage from two hosts with good networking  
- **Hyper-V vs VMware**: Consider Hyper-V 2016 for newer features, but VMware offers greater OS flexibility  

**Windows Server Choice**  
- Windows Server 2016 is generally preferable over 2012 R2 for better performance and security  
- However, if you're already invested in VMware, 2016's features may not justify waiting  

**Critical Lessons from Past Upgrades**  
1. **Avoid Over-Complication**: Prioritize simplicity. If you feel overwhelmed, you've overcomplicated the plan  
2. **Legacy Hardware Risks**: Be aware of old hardware like fax cards or USB dongles that may not work in virtual environments  
3. **Storage Planning**: Be extremely generous with storage capacity. Virtualization creates significant overhead for VMs, replicas, and backups  
4. **Don't Over-Commit Resources**: Smaller, more modern hosts often outperform expensive, older ones with fewer cores  

**Business-Driven Approach**  
- Use a scoring system (1=must-have, 2=nice-to-have, 3=optional) to align technical choices with business needs  
- Consider hybrid models: Maintain on-premise infrastructure for now while planning gradual cloud migration  
- Evaluate cloud options for email (like Office 365) and data security, but keep core systems on-premise for control  

**Implementation Tips**  
- Migrate physical servers to virtual machines (P2V) only if you can fully transition to the new OS in the VM  
- Leverage your existing VMware experience with vCenter and ESXi for smoother deployment  
- Always test configurations in non-production environments before rolling out changes  

Remember: The goal is to create an infrastructure that supports your core business applications, not just to virtualize everything. Focus on reliability, scalability, and cost-effectiveness while maintaining technical flexibility for future growth.
