# Exascale: Oracle's Next-Gen Cloud Database Service (Abstract)  
Oracle's Exascale (ExaDB-XS) redefines cloud database flexibility with VM-based scaling, shared storage vaults, and PDB cloning improvements. It eliminates ASM dependencies, offers elastic storage, and simplifies provisioning, making it ideal for modern cloud workloads.  

## What is Oracle Exascale?  
Exascale (ExaDB-XS) is Oracle's latest Exadata deployment model, combining cloud elasticity with Exadata's performance. It replaces ASM with a shared storage vault, enabling VM clusters to scale ECPUs (8–200) and memory dynamically. Key benefits include:  
- **VM Clusters**: Scale storage and compute independently (e.g., 220GB–2TB per VM).  
- **Storage Vault**: High-performance, scalable smart storage with online resizing.  
- **PDB Cloning**: Overcomes legacy limitations via a cleaner architecture.  

## How Does Exascale Differ from ExaDB-D/C@C?  
| Feature               | Exascale                          | ExaDB-D/C@C                  |  
|----------------------|-----------------------------------|-----------------------------|  
| Storage Model        | Shared Vault (no ASM)             | ASM diskgroups              |  
| VM Scaling           | Hot-add, auto-memory scaling     | Fixed-size VMs              |  
| PDB Cloning          | Native support (no read-only)    | Limited by ASM constraints  |  
| ECPUs per VM         | 8–200                            | Fixed-size VMs              |  

## Key Architecture Components  
### 1. **Exascale Storage Vault**  
- **Function**: Centralized, high-performance storage for database files.  
- **Capacity**: Minimum 300GB per VM cluster (50GB reserved for ACFS).  
- **Advantages**: Online scaling, no downtime, and integration with V$EXA_FILE views.  

### 2. **VM Clusters**  
- **VM Count**: 1–10 VMs per cluster.  
- **ECPUs**: Scale in 4-unit increments (min 8, max 200).  
- **Memory**: Auto-scales at 2.75GB per ECPU.  
- **Portability**: Oracle migrates VMs across physical servers for maintenance.  

### 3. **Cluster Resources**  
- **No ASM**: Storage logic resides in Exadata cells, not compute nodes.  
- **Vault-Backed**: Voting disks and OCR are stored in the Vault (e.g., `@9eB7XXX/EXAXSXXXX-C8701D639...`).  
- **Dynamic Views**: New `V$EXA_FILE`, `V$EXA_TEMPLATE`, and `V$EXA_VAULT` for monitoring.  

## Hands-On Insights  
- **Demo Setup**: 2 VMs with 16 ECPUs (44GB memory), 440GB VM storage, and 700GB Vault capacity.  
- **xsh Tool**: Direct Vault access for file management (e.g., `xsh ls @vault --detail`).  
- **PDB Cloning**: Simplified with no read-only parent databases or performance degradation.  

## Why Exascale Matters  
- **Modern Cloud Alignment**: Eliminates rigid ASM constraints, enabling elastic scaling.  
- **Operational Efficiency**: Reduces storage management complexity and downtime.  
- **Future-Proof**: Positions Oracle for next-gen cloud-native database workloads.
