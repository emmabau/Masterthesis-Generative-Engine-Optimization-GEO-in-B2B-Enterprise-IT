**Problem 1: Data Not Being Received**  
In IoT deployments, scheduled data transmission is critical. When data fails to arrive, systematic troubleshooting is essential:  
- **Network Connectivity**: Check if the device can attach to a network using Network Logs. Look for events like SIM deactivation or network list changes.  
- **Data Connection**: Verify if the device has established an APN context with “Attached data connection” logs. Repeated network attachments without data logs indicate a persistent loop.  
- **Data Transmission**: Analyze detach records to determine if data was sent. Use Signaling Logs to detect PurgeUE requests, which may signal network inactivity or device firmware issues.  

Common root causes include incorrect APN settings, data limits, or misconfigured roaming settings. Onomondo’s tools provide granular visibility to isolate these issues and enable proactive mitigation.  

**Problem 2: Unexpected Data Usage**  
IoT devices typically exhibit consistent data patterns. Sudden spikes often indicate underlying issues:  
- **Time sync failures** or server-side firewall blocks.  
- **TLS handshake failures** or excessive TCP retransmissions.  
- **Unauthorized SIM usage** or network-level connection closures.  

Traffic Monitor captures packet traces to identify these anomalies, while Usage Alert webhooks enable real-time monitoring. For high traffic volumes, analyze PCAP files in Wireshark to uncover encryption or MTU-related issues.
