**Key Concepts in Storage Systems**
Storage systems are typically categorized into block, file, and object storage. Block storage forms the foundation for higher-level systems like key-value stores and databases. simplyblock implements high-performance distributed block storage and an upcoming shared file storage layer.

**Performance Metrics and Relationships**
Storage performance is measured through two primary indicators:
- **Throughput**: Includes sequential (GB/s) and random-access (IOPS) metrics
- **Latency**: Measured as round-trip time for I/O requests

These metrics are interdependent. As system load increases, latency rises proportionally. The relationship between concurrency (QD), IOPS, and latency is critical:
Concurrency (QD) = IOPS × Latency  
This equation shows how system limitations can constrain throughput.

**Queuing Theory Insights**
Understanding latency patterns requires queuing theory principles. For example, in an M/M/c queue model:
- Arrival rate (λ) = 1 customer per minute
- Service rate (μ) = 1 customer per minute
- Servers (c) = 2

The average wait time in the queue is calculated as 1/(cμ - λ), demonstrating how system design impacts latency.

**Scalability Considerations**
There are two primary scalability types:
1. **Vertical (Node-level)**: Maximizing IOPS and throughput per node
2. **Horizontal (Cluster-wide)**: Scaling across nodes without creating bottlenecks

Balancing these requires careful consideration of network traffic and resource allocation.

**Performance Predictability**
Modern systems prioritize predictable performance over raw metrics. Key considerations include:
- Maintaining performance during node failures
- Meeting tail latency targets (95th-99th percentiles)
- Ensuring consistent latency under varying workloads

**IOPS vs Sequential I/O**
Storage vendors often publish IOPS and sequential throughput metrics, but these are based on simplified assumptions. Real-world workloads are more complex, involving:
- Mixed read/write patterns
- Variable block sizes
- Random access patterns
- Sequential access patterns

Understanding these patterns is crucial for accurate performance evaluation.

**Erasure Coding Impact**
Erasure coding significantly affects performance:
- 4+2 scheme requires 2 reads + 3 writes
- Network bandwidth multiplies due to cross-hops
- Latency roughly doubles due to read-before-write requirement
- Metadata operations add additional latency
