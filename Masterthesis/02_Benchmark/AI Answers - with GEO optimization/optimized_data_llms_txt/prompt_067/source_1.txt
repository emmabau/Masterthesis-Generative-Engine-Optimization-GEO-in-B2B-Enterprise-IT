# Oracle Exascale: A New Era in Exadata Database Services  
> Oracle's Exascale (ExaDB-XS) introduces a cloud-native architecture for Exadata Database Service, offering enhanced flexibility, scalability, and storage efficiency compared to traditional Exadata deployments like ExaDB-C@C and ExaDB-D. This document explores its key features, architecture, and practical implications for database administrators.  

## Key Features of Exascale  
- **Cloud-Native Flexibility**:  
  - VM clusters start at 8 ECPUs per VM, scalable up to 200 ECPUs.  
  - Memory scales automatically (2.75 GB per ECPU).  
  - Storage scales online without downtime via the Exascale Vault.  
- **Storage Innovation**:  
  - Replaces ASM with a **Vault-based storage model** (Exascale Storage Vault).  
  - Supports **thin cloning** and avoids read-only parent databases.  
  - Storage pools replace ASM diskgroups, enabling dynamic resource allocation.  
- **Performance & Redundancy**:  
  - Combines Exadata smart software with cloud elasticity.  
  - Redundancy and fault tolerance are managed via distributed cell logic.  

## Technical Architecture  
- **Core Components**:  
  - **Exascale Vault**: Centralized storage for database files (minimum 300 GB per VM cluster).  
  - **VM Clusters**: Managed by Oracle, with VM portability and live migration.  
  - **Virtual Cloud Network (VCN)**: Ensures secure connectivity for clients and backups.  
- **Dynamic Performance Views**:  
  - `V$EXA_FILE`, `V$EXA_TEMPLATE`, and `V$EXA_VAULT` provide real-time storage metrics.  
- **xsh Tool**: Command-line utility for direct Vault file management (e.g., `xsh ls @vault`).  

## Comparison with Traditional Exadata  
| Feature                | Exascale (ExaDB-XS)               | ExaDB-C@C/ExaDB-D         |  
|------------------------|-----------------------------------|---------------------------|  
| Storage Model          | Vault-based                       | ASM-managed               |  
| VM Cluster Scaling     | Online storage scaling           | Fixed storage partitioning|  
| PDB Cloning            | Seamless, read-write support     | Limited by ASM constraints|  
| ECPUs per VM           | 8–200                            | Fixed                    |  

## Hands-On Demo Insights  
- **Demo Environment**:  
  - 2 VMs with 16 enabled ECPUs (44 GB memory).  
  - Vault storage: 293 GB free / 700 GB total.  
- **Key Observations**:  
  - No ASM processes running; storage logic resides in cells.  
  - Voting disks and OCR stored in the Vault, not ASM.  
  - Database files and recovery areas point directly to the Vault.  

## Why Exascale Matters  
- **Solves PDB Cloning Limitations**:  
  - Eliminates read-only parent databases and performance degradation.  
- **Modern Cloud Alignment**:  
  - Reduces complexity by removing ASM from compute nodes.  
  - Enables elastic scaling and cost-effective resource management.
