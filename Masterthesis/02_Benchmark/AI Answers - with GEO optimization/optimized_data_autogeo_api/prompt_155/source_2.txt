## The Control Plane as the Product  
**Q: How does policy-defined infrastructure prevent sprawl?**  
A: By treating infrastructure as code, control planes enforce guardrails. For example, Open Policy Agent (OPA) allows rules like “no public load balancers without approved tags” to be enforced across Kubernetes, CI/CD, and microservices.  

**Q: What are the four pillars of composable infrastructure?**  
A:  
1. **Catalog of building blocks**: Compute, storage, security, and data services.  
2. **Intent declaration**: Define workload needs, not manual wiring.  
3. **Policy engine**: Enforces guardrails (e.g., zero-trust encryption, cost ceilings).  
4. **Automation**: Provisions, observes, and retires resources via GitOps reconciliation (e.g., Flux, Argo CD).  

## Real-World Retail Use Case: Peak-Week Resilience  
**Q: How does composable infrastructure handle high-traffic events?**  
A: Intent-driven orchestration assembles resources automatically. For example:  
- **Compute**: Autoscaled microservices for cart/checkout.  
- **Security**: Mandatory encryption for customer data (aligned with NIST Zero Trust).  
- **FinOps**: Budget ceilings and cost tagging enforced at provisioning.  

**Q: What governance mechanisms prevent sprawl?**  
A:  
- **Time-to-live**: Resources expire unless renewed by policy.  
- **Deny-by-default**: Public endpoints require explicit approval.  
- **Reconciliation**: Drift is corrected via continuous GitOps sync.
